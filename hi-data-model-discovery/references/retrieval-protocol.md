# Data Retrieval Protocol

Use `mind_mcp`, scoped graph semantic candidates, verified graph relationships, Serena confirmation, then `rg` for SQL, migrations, annotations, ORM mappings, configuration, cache keys, and schema identifiers. Fast-fail unavailable capabilities once.

Verify repository/project/database/collection identity. Prefer declared schema and migration evidence for physical constraints; use ORM/domain/DTO/cache usage as separate layers. Confirm readers, writers, owners, and lifecycle policies from code or configuration rather than naming alone.

Record dynamic SQL, reflection, external schemas, generated models, missing migrations, and runtime-only retention as gaps. Never infer a foreign key, cardinality, uniqueness, owner, sensitivity, or retention rule into a verified declaration.
